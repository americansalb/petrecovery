# Mobile setup — building the ReunitePets app

The runbook for turning this repo into an installable iOS (and Android) app.
Phase 1 only: the app loads the live website (full parity). Background GPS,
offline, and push come in later phases (docs/MOBILE_APP_PLAN.md).

Everything in the repo is already wired (config, native seam, app bootstrap).
The steps below are the parts that **must** run on a Mac with Xcode — they
generate and sign the native project, which can't be done on a Linux server.

---

## What's already done in the repo

- `frontend/capacitor.config.ts` — points the app at `https://www.reunitepets.org`.
- `frontend/capacitor-www/` — offline fallback page.
- `frontend/app/lib/native.js` — native detection seam.
- `frontend/app/components/CapacitorBootstrap.js` — splash/status bar/deep
  links/back button, active only inside the app.
- Capacitor dependencies + `cap:*` scripts in `frontend/package.json`.

You do **not** need to run `npx cap init` — the config already exists.

## Prerequisites (Mac)

- macOS with **Xcode 15+** (from the App Store)
- **Node 18+** and **CocoaPods** (`sudo gem install cocoapods`)
- Your **Apple Developer account** (you have this)
- For Android (optional now): **Android Studio**

## Steps

```bash
cd frontend

# 1. Install dependencies (pulls in Capacitor)
npm install

# 2. Generate the native iOS project (one time)
npm run cap:add:ios
#    Android too, when you want it:
#    npm run cap:add:android

# 3. Copy config + web assets into the native project
npm run cap:sync

# 4. Open the project in Xcode
npm run cap:open:ios
```

In Xcode:

1. Select the **App** target → **Signing & Capabilities**.
2. **Team:** choose your Apple Developer account. Bundle id is already
   `com.reunitepets.app`.
3. Plug in your iPhone, pick it as the run target, press **▶ Run**. The app
   installs and opens straight onto the live site.

## Ship it to your phone / testers (TestFlight)

1. In Xcode: **Product → Archive**.
2. When the Organizer opens: **Distribute App → App Store Connect → Upload**.
3. In App Store Connect → **TestFlight**, add yourself/testers. They install
   via the TestFlight app.

## The magic part: updating the app

Because the app loads the live website, **you do not rebuild or resubmit for
normal changes.** Ship the website and the app updates itself the next time
it's opened.

You only repeat the Xcode build + upload when the **native shell** changes —
a new plugin or permission (e.g. when background GPS lands in Phase 2).

## Dev mode (live reload against your laptop)

To point the app at a local dev server instead of production:

```bash
# terminal 1
npm run dev

# terminal 2 — use your machine's LAN IP, not localhost
export CAPACITOR_DEV=true
export CAPACITOR_DEV_URL=http://192.168.x.x:3000
npm run cap:sync && npm run cap:open:ios
```

## Notes

- `ios/` and `android/` are generated by `cap:add`. Commit them after the
  first generation if you want to customize native files (icons, Info.plist,
  permissions); their build outputs are gitignored.
- Point the app elsewhere by setting `CAPACITOR_SERVER_URL` before `cap:sync`.
- Apple review note for later submission: the app will request background
  location for volunteer search-and-rescue (Field Mode) — call this out in the
  review notes to clear Guideline 4.2.
